# Logo 多用户生成调度

现有单图、多产品、多 Logo 的后台生成入口已经接入。保留原有账号、产品、任务草稿、进度和历史格式。付费生成开关仍关闭，接收的业务任务显示“已排队，等待启用生成”；原有本地银箔处理可独立完成。私有 OSS 传输和异机备份通过独立角色启用，付费生成启用前仍需确认账号额度。

## 流程

页面账号鉴权 → 准备与校验图片 → 持久化批次及不可变图片参数 → 原子提交批次 → 按用户轮流分配 → 提交 / 查询 / 下载 → 独立图片处理 → 原有进度和历史。

批次全部输入保存后才返回 202；未提交的批次不发起上游请求。完整 PREPARING 批次重启后继续提交，不完整批次超过十分钟自动终止。重启恢复通过 PostgreSQL 按账号和任务查找，不依赖页面或内存映射。后台扫描分页覆盖所有待更新批次。

## 配额和隔离

- 默认不限制尚未完成的远端生成总数（`PROVIDER_MAX_RUNNING=0`）；拿到任务 ID 后立即释放提交位置。只有服务商确认存在持续生成额度时才配置正值。每用户 2 张是公平优先目标，不是必须等生成完成才能提交下一张的硬上限；有其他用户等待时按用户轮流提交，只有一人时继续提交其待办。
- 提交 HTTP 同时最多 2 个，发起间隔至少 500 ms；不需要等前一张图片生成结束。查询限速 300/min。
- 每用户最多 200 张待处理图片；多产品、多 Logo 每张分别调度。
- 每张图片任务的内部提交数据上限为 64 MiB；重复图片通过引用传输，保存前还原原始图片和参数。这是任务数据包上限，不是成图文件大小。
- 下载同时 2 张，图片处理同时 1 张，图片库每张使用 2 个线程；阶段租约只分配至可执行容量，并持续续租。
- 实际提交执行前再次检查付费开关，关闭后 Redis 中未发出的旧任务也会安全退回队列。
- 提交结果不确定时不自动重发，持久化待核查；默认不占用后续任务的提交位置。下载和处理失败在参数未修改时沿用已成功的上游结果重试。
- 旧生成流程的有效 checkpoint 经请求指纹验证后接续，不重复 POST。
- 独立 PostgreSQL、Redis 私网，不发布数据库端口；API 仅 `127.0.0.1:3320`，内部 token 和可信账号只由网页服务传入。
- 网络服务和图片服务分开，CPU 配额分别 0.5/2 核。数据库 512 MiB、Redis 256 MiB、API 512 MiB、网络 512 MiB、图片 768 MiB，新增上限合计约 2.5 GiB。
- 图片准备目前在网页服务内完成，未全部迁至独立图片服务；高分辨率的印刷遮罩合成在图片 Worker 内完成。仍需使用真实大图进行混合压测。

## 持久化和恢复

目录 `/srv/logo-scheduler`、`/etc/logo-scheduler`、`/var/lib/logo-scheduler`。模型凭据仅保存在受保护的配置，沿用 Logo 专用网络路由，不读取 FRAME 配置。网页通过 `/etc/s7-logo/scheduler.json` 访问调度器，浏览器不获取 token。

不可变计划采用 SHA-256 内容寻址、写入同步后原子重命名；数据库只记录指纹。历史按调度 job ID 幂等写入，重启时重复回填不会重复生成历史条目。图片保留原分辨率和现有印刷遮罩算法，不用缩小预览替代最终成图。

低于 2 GiB 暂停新任务和提交，低于 1 GiB 暂停下载。Redis 使用 AOF 和 noeviction。数据库是事实来源，Redis 丢失唤醒可以恢复。

每日 02:50 Asia/Shanghai 执行备份，本地保留七份，包含数据库及不可变计划与图片；每次隔离恢复数据库，并验证计划文件指纹。配置独立存储角色后同时写入 OSS 异机副本。不得删除其他服务的备份腾空间。

## 私有 OSS 接入

配置 `LOGO_OSS_STORAGE_ROLE_ARN` 后，使用独立 `LogoSchedulerStorageRole`，通过 ECS 原有身份换取临时凭据，不创建长期 AccessKey。仅允许 `heci-002/s7-logo/generations/v1/` 与 `heci-002/s7-logo/scheduler-backups/v1/` 的读、写和目录列表，不授予删除或公共访问。

图片 Worker 保留原尺寸 PNG，并创建单独的 1200 像素 WebP 预览，通过内网上传并完整读回校验。上传暂时失败时本地成图仍可查看；每分钟只重试存储，不重新生成或重复处理完整图片。同步后回填同一历史记录。图片路由先检查当前用户及任务所有权，再返回 60 秒外网签名地址；签名服务异常时回退本地文件。旧图片继续使用本地存储，不自动迁移或删除。启用前须验证 `https://logo.heciai.net` 的 GET/HEAD 跨域读取与 CSP；保留 FRAME 已有跨域规则。

批量下载先校验当前任务中所选图片的所有权，再向浏览器返回文件清单；浏览器同时读取最多两张原图，逐张经过鉴权取得新签名，在本机打包 ZIP。新生成图片的批量下载不再由服务器转发完整图片与 ZIP。保留 200 张、300 MB 的单次上限，超出时要求分批下载；旧本地图片或签名故障时的回退仍使用服务器带宽。

现有备份任务在本地恢复验证后上传数据库和图片/参数归档，流式完整读回并核对 SHA-256，全部通过后最后上传完成清单，写入 `last-offsite-success.json`。云端失败不会记录备份成功。每个文件限制 4 GiB，超过时停止并提示，不生成不完整的成功清单。云端未设置自动删除或保留期；本地七份保留规则不代表云端保留期。

上线验收须覆盖云角色、真实内网上传、外网私有读取、实际 S7 页面 CSP 和异机备份，不能只验证 SDK 或用模拟队列代替。

## 验证

S7 原色、黑白、烫金、烫银方案具备定位图与遮罩时均作为本地任务处理，`local` 生成方式无需 APIMart 配置，在付费生成关闭时仍可处理。原色与黑白使用定位贴图，金银使用本地材质合成；图片保存与 OSS 同步沿用原队列流程。

`npm test` 使用独立 `scheduler_test` 与 `scheduler_acceptance`，不读取生产 DATABASE_URL。business.test.mjs 通过真实三个 HTTP 入口验证批次、用户隔离和重启恢复；模型是模拟边界，不调用付费服务。

`acceptance.mjs` 必须明确提供 ACCEPTANCE_DATABASE_URL（路径仅允许 /scheduler_acceptance）和 ACCEPTANCE_REDIS_URL。15 用户每人 10 张，共 150 张模拟图片；先让全部任务取得 ID，再允许任何远端任务完成，验证提交不被持续生成数卡住、公平第一轮、下载重试不增生成次数、Worker 重建与唤醒丢失。另有数据库测试覆盖用户错峰到达。它不能替代真实大图、实际网络和其他软件高峰压测。

## 运维

`SUBMISSION_UNKNOWN` 只能核实上游受理记录后处理；禁止批量重新生成。无结果链接的远端成功需要人工获取，网页重试不会悄悄重新收费。旧、新生成链路在启用调度时不可同时执行；同步旧端点不再绕过调度。

未来迁机需一起迁移 PostgreSQL、Redis、不可变计划、结果和已有用户任务目录；恢复时先保持付费关闭。回退保留所有数据与受保护配置，禁止 `docker compose down -v`。
