# 批量去除 Logo 占位字

主工作区侧栏入口：**批量去占位字**，地址 `/#/modules/logo-cleanup`。更新后安装依赖并重启主工作区服务；本模块不需要单独启动端口。

默认流程：多选添加图片 → 点击“一键自动去字” → 自动识别并修补 → 原图对比 → 下载 PNG 或已完成图片 ZIP。新上传图片默认勾选，也可只勾选部分未完成图片。无需逐张框选或逐张生成；同时处理最多 3 张，其余自动排队。已有手动框的图片直接使用现有框；未识别到占位字的图片标为“待核对”，不调用修补接口，也不冒充完成。可切换批次，刷新页面会恢复已保存内容；关闭页面不打断服务端处理。失败图片可单独重试，自动批量重试跳过已完成图片。

正式调用链：主工作区 `/logo-cleanup/` 页面 → `POST /logo-cleanup/api/batches/:id/auto` → 服务端 `provider.detect()` → `provider.remove()` → 原 APIMart 模型首次提交一次生成 → `restoreOutsideRegions(..., {blend:true})` 自动完成笔画与底色融合 → 保存最终 PNG 并标记完成。融合属于保存前的固定步骤，不需要第二个模型或操作人员下载后再处理。`work/` 下的诊断脚本不在服务运行依赖中；线上部署需要同步本模块源码、主工作区路由和 npm 依赖并重启主服务，本机更新不会自动发布到线上。

需要先看框时，使用“仅识别占位字”，核对/调整框后点击“按已有框去字”。两项批量操作同样只处理勾选的未完成图片。自动识别范围仍为下述占位字，不代表能识别任意普通品牌文字；普通品牌字、倾斜与交叉字样可人工补框。

识别在本地执行，匹配 `YOUR LOGO`、`Private Label`、`LOGO HERE`、`CUSTOM LOGO`，包括大小写、横排、竖排及部分倾斜方向。英文 OCR 数据随 npm 依赖安装，运行时不下载识别模型，也不调用远程视觉模型。漏识别的字样可在原图拖动补框；框内拖动可移动，右下角可缩放，Delete 可删除。重新识别某图会替换该图已有的框，因此应在手动修正之前识别。

修补复用 `S7_AI_CONFIG` 或 `data/ai-provider.local.json` 中的 APIMart endpoint、apiKey、proxyUrl、timeoutMs，调用 `gpt-image-2.5-flare`（需要相应模型权限）。发送原图和透明区域遮罩。对于边界完整、表面较平滑的区域，使用四边逐位置插值估计瓶身底色，按背景残差自动确定文字对比阈值，将笔画及压缩杂点周围 6–12 像素纳入修补范围。通过局部 Poisson 方程融合 AI 的细节变化与原图边界颜色，仅在笔画外侧做过渡，框内其余像素直接保留原图。复杂纹理、密集残差或缺失边界无法可靠细分时，改用框内修补与边界颜色匹配；不能保证任意材质都能准确分割笔画。

框外的 RGBA 像素取自上传后归一化的原图，尺寸不变，统一导出 PNG。上传图按 EXIF 转正并转成 sRGB PNG，所以保留的是视觉内容和框外解码像素，不是原 JPEG/WebP 文件字节或元数据。框外漏选的文字仍需调整框，复杂材质或交叉位置的修补结果需要核对。

原图、结果、批次和远端任务 checkpoint 保存在 `APP_DATA_DIR/logo-cleanup/<用户 ID 的 SHA-256>/<批次 ID>/`，与工作区账号隔离。每个服务实例的全部账号和批次共享 3 个处理名额，单张任务完成后自动释放名额；单图失败不影响其他图片。服务重启后未完成图片标记为可重试，已保存的远端任务优先继续查询/下载。上游生成图片无法解码或比例不符时清除 checkpoint，使下一次重试可以重新生成。

限制：每批 100 张；单张 12 MB / 1600 万像素；静态 PNG、JPG、WebP；每批归一化原图 300 MB，ZIP 导出 300 MB。单图最多 80 个框；单框最多占图面积 15%，合计不超过 40%。本地批次不自动清理，属于新增存储目录。

已验证用户样图：第一张识别 2 处，第二张识别 5 处，保留尺寸、重量、标题、色块和净重；新增亮色文字二值化识别，粉色唇釉图可分别识别四支瓶身上的白字，避免原有流程仅找到中间两支。交叉唇线笔图的倾斜和遮挡字样可能漏识别，需要人工补框。识别不是语义理解所有品牌文字，不应直接当作全自动无审核流水线。材质修补仍需要查看成图，必要时调整框后重试。

验证：`npm test` 包含本模块测试；单独运行 `node --test test-logo-cleanup.mjs test-logo-cleanup-integration.mjs`。覆盖自动识别到修补的完整流程、批次间共享并发、未匹配转核对、失败重试、已完成跳过、手动框保留、白色笔画贴框边、曲面色差、框内非文字像素保留、压缩杂点及高光上低对比白字的回归。`pipeline.test.mjs` 通过真实 HTTP 接口上传没有框的样图，使用真实 OCR 和 Provider，只有远端网络被替换为一次已记录的 AI 成图；断言一次生成、四处文字清除、框外像素与框内干净边角保留，并直接从正式结果和 ZIP 接口读取成图。其他 API 测试使用临时目录和假 Provider，不消耗真实图片模型额度。金属软管与粉色唇釉样图作为回归夹具，不作为用户图库的种子数据。

接口协议参考：[APIMart GPT Image 2.5 图像编辑及透明遮罩](https://docs.apimart.ai/en/api-reference/images/gpt-image-2.5/generation.md)、[Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)。
