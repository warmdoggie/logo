## 3. SKU 修改及历史完整性

操作路径：产品图库 → 编辑产品 → 修改 SKU → 填写修改原因 → 保存 → 阅读影响数量并确认。

系统保持 Product ID 不变，校验新 SKU 格式和唯一性；记录原编号、新编号、原因、操作人和时间。已有任务继续通过 Product ID 关联，任务详情同时提供当前 SKU 和任务创建时 SKU。旧任务资料在产品修改前补充快照；已经存在的快照不覆盖。

材质、表面处理变更追加产品工艺资料版本。影响规则匹配的旧任务资料通过快照保留，避免产品资料维护直接改写旧结果。SKU 条件规则不自动改名，保存提示会要求另行核对规则条件。

验证示例：测试产品 B000 → RENAMED-SKU → UI-SKU-2026，修改原因和历史均可见。自动测试比较修改前后的任务关联、母版、效果图、审核、批次、风格和规则评估记录，均未被重写；重复 SKU 和缺少确认均被拒绝。

## 4. 标准图 V1 → V2 演示及母版关系

操作路径：编辑产品 → 上传新版标准图 → 勾选母版风险确认 → 选择更新后操作 → 保存新图片版本。

![标准图V1到V2](../Step6A2页面截图/03-产品图V1到V2.png)

原图文件不覆盖。标准图版本保存文件路径、校验信息、尺寸及版本关联。旧任务继续使用已绑定图片；新任务锁定新的标准图和资料快照。新图与当前母版图片不同的时候，不会把旧母版静默套到新图上，母版编辑器提示重新建立或确认区域，发布后成为新的母版版本。此前已经绑定旧母版的任务不切换。

自动测试使用 400×300 的 V1 与 500×350 的 V2：旧任务仍使用 V1；新任务使用 V2 且不会误绑 V1 母版；发布 V2 母版后，再创建的任务才使用新母版。历史任务不会因为后续发布而自动换版。

兼容说明：迁移不批量改写旧记录。第一次打开产品编辑或创建绑定时，会登记旧图的 V1 版本信息；首次资料修改前会补充必要的旧任务快照。

## 8. 删除防误删与失败恢复

删除先计算任务专属记录，再检查关联文件是否被其他记录引用。Product、产品图、ProductTemplate、TemplateZone、共享 Rule 不在任务删除清单内；同一文件仍被其他任务或共享资料引用时保留。

文件路径限制在当前项目 data 目录，校验文件名和真实路径，拒绝越界与文件符号链接。预览生成指纹，正式提交重新核对数据与文件，避免直接使用过期预览。

清理过程先写恢复清单，再在数据库事务内移除专属记录并将可删除文件移动到临时区；提交成功后清除暂存文件。数据库或移动失败时回滚并还原文件；进程中断后根据 PREPARED / COMMITTED 状态恢复或完成清理。未完成操作在存储页面提示并在下次启动重试。恢复清单和审计记录保留用于追溯。

本版实现管理员永久删除及内部恢复机制，没有提供用户可操作的回收站或撤销删除功能。日常暂时隐藏任务请使用归档。

故障注入测试人为增加外键阻挡提交，确认数据库回滚、文件恢复；随后解除阻挡完成删除。测试还模拟 PREPARED、COMMITTED 中断后的重新启动，并验证共享 Logo 文件与产品母版保留。测试输出中的一次 FOREIGN KEY constraint failed 是该预期故障注入，不是正式项目错误。

## 9. TEST / FORMAL 规则隔离

Rule.isExample=1 映射为 TEST，0 映射为 FORMAL。规则列表有环境标记和筛选，原示例规则默认禁用状态不变。即使启用 TEST 规则，也不参与正式任务判断；专用测试任务才允许执行已启用 TEST 规则。

![规则环境标记](../Step6A2页面截图/07-TEST与FORMAL规则标记.png)

测试路径：管理员登录 → 新建专用测试任务 → 在任务详情设为测试任务 → 开始规则预审。已经预审或生成效果图的任务不能切换环境。正式项目原任务没有被批量设为测试任务，名称带“测试”也不会自动改变环境。

已验证相同启用的 TEST BLOCK 规则：正式任务不受其阻挡，测试任务按预期阻挡。原 Step 4 测试中“启用示例阻挡正式任务”的旧预期已按此明确的新要求调整。
