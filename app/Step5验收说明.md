# Step 5 效果图工作台与首图生成交付说明

完成日期：2026-09-14。沿用本机 Node 服务、SQLite 和上传文件目录。访问地址 http://127.0.0.1:3210/ ，双击启动方式不变。

## 1. 已完成功能清单与使用路径

任务中心 → 查看任务 →「效果图工作台」。应用路由为 `/#/tasks/[taskId]/workspace`。

- 三栏工作台：任务 SKU 与状态列表、锁定产品画布、Logo / 工艺控制。
- 自动读取任务绑定的母版版本和母版对应产品图；无绑定母版时明确提示，不采用最新母版代替，不推测 Logo 位置。
- 读取当前生产 Logo 及其来源原始版本、颜色模式、色数和颜色备注。工作台只移动、等比缩放、旋转 Logo，不修改原图或 Logo 内容。
- 默认区域、默认中心、尺寸上限和方向来自锁定母版。多个区域没有默认值时，要求先选择区域。
- 支持拖动、右下控制点缩放、数值输入、中心参考线和区域显示开关。横向 / 纵向 / 自由方向和是否允许旋转共同限制操作。
- 超出允许区域、尺寸上限或碰撞禁止区域时显示提示，并阻止生成；服务端重复校验，不能通过直接调用接口绕过。
- 每个 SKU 独立保存草稿，调整后延迟自动保存；切换 SKU 或离开工作台前尝试保存，保存失败时提示；浏览器关闭时对未保存内容提醒。
- 工艺来自 Step 4，禁止和待补资料的候选不可生成；推荐方案可切换。每次生成前重新预审，WARNING 要求新的确认说明。
- 服务端输出真正的 PNG 文件。生成、调整、重新生成、历史查看、单张下载及六项人工审核均可操作。
- 首图确认后建立 Task Style Master。可手动设置首图 SKU；默认优先选择具有绑定母版且存在正式 PASS 候选的 SKU。
- 当前生产 Logo 切换后，工作台提示并重新加载，新生成保存为新版本；旧效果图不修改。

### 您当前正式任务的注意事项

正式库中的三个旧任务目前均未绑定母版版本，工作台会显示「缺少任务绑定母版」。这是需求文档规定的前置校验，没有给旧任务自动回填。

## 4. 新增数据库结构与迁移

新增 `mockup-schema.sql`，启动时创建以下六张表和索引。未重构或增加 Step 1–4 原表字段。

| 表 | 保存内容 |
| --- | --- |
| ProductImageVersion | 产品引用、锁定图片路径、SHA-256、实际宽高和时间；为效果图保留底图依据 |
| MockupJob | 每个任务产品的草稿、锁定图片和母版、当前生产 Logo、区域、标准化位置、等比宽度、旋转、工艺、状态和草稿修订号 |
| MockupVersion | 每次生成的独立图片、版本、生产 Logo、图片 / 母版版本、规则评估引用、完整渲染快照和文件摘要 |
| MockupReview | 人工审核或返回调整记录、六项确认、操作者和时间；审核记录追加保留 |
| TaskStyleMaster | 任务级风格基准版本、生产 Logo、工艺、颜色 / 视觉模式及来源效果图 |
| TaskWorkspaceState | 当前首图 SKU、首图流程状态、风格基准引用和并发修订号 |

首次保存工作台草稿时锁定图片版本。历史任务不会迁移成带母版的任务；只读打开工作台不会生成草稿或测试效果图。

原 Task 状态字段保持原样，首图状态由新增工作台表保存，等价支持 `READY_FOR_FIRST_RENDER → FIRST_RENDER_REVIEW → FIRST_RENDER_APPROVED`。返回调整回到待生成状态；未来批量入口预留，但本阶段未实现。

生成时通过既有 LogoUsageReference 追加当前生产 Logo 的使用引用，供既有版本追溯读取，不覆盖原 Logo。

## 5. Mockup 版本管理

- 每个 TaskProduct 对应独立 MockupJob，草稿修订号保护多页面并发保存；过时提交被拒绝。
- 每次成功生成使用新文件名，追加 MockupVersion V1、V2……，不覆盖旧图。
- 每版快照记录位置、宽度、角度、工艺、Logo / 母版 / 图片版本、规则评估及文件 SHA-256。
- 旧版本只读；确认必须针对最新版本，且草稿未调整、当前 Logo 未变、规则仍然有效。
- 生成期间发生草稿或 Logo 变化时停止保存该结果；同 SKU 并发生成拒绝重复执行。
- 六项审核为内容、位置、大小、方向、颜色 / 工艺视觉、产品本体未变。未完成不能确认。
- 同一已确认版本重复提交不创建重复风格基准；重新生成并确认后可建立新的基准版本。

## 6. Task Style Master 结构与用途

结构：`id、taskId、version、productionLogoId、processType、colorMode、visualMode、sourceMockupJobId、sourceMockupVersionId、createdAt`。

确认首图后建立任务风格基准 V1；它保存本次客户 Logo 的颜色与工艺方向，以及可追溯的来源效果图，不保存某个 SKU 的绝对像素位置。后续 Step 6 应读取每个 SKU 自己的 Product Template 完成摆放。

## 7. 规则引擎联动方式

工作台继续使用 Step 4 的 `ruleService`，未新增另一套制造规则判断。工艺候选根据当前区域读取规则，生成前再次保存预审快照。

- PASS：通过当前资料检查后可生成。
- WARNING：每次生成前重新预审并要求二次确认，保存确认说明；不会直接沿用之前另一轮的警告确认。
- NEED_INFO / BLOCK：服务端拒绝生成，页面给出补资料或替代工艺入口。
- 示例规则：不作为正式放行依据。
- 规则、工艺、区域、资料或当前 Logo 变化后，旧评估不可用于生成 / 首图确认。
- 黑 / 白 / 金 / 银及对应烫印视觉要求使用 Step 3 对应预设颜色的单色生产 Logo；颜色不匹配时提示返回 Step 3。普通印刷直接采用现有生产 Logo 色彩。工作台不会偷偷给 Logo 换色。

统一渲染入口为 `POST /api/render`，保留文档中的任务、任务产品、Logo、母版、区域、位置尺寸旋转和工艺字段，并增加草稿修订号与评估编号，用于阻止旧参数或旧预审被提交。

## 9. 简化模拟和后续能力

- 当前为二维、等比、无透视的 Logo 合成，使用完整 Logo 图层边界检查区域和碰撞，比较保守。
- 输出 PNG，支持单张下载；未增加 JPG 格式选择、批量页面或 ZIP 导出。
- 黑、白、金、银使用 Step 3 对应颜色版本；金银和烫印未模拟真实金属反射。
- 未实现曲面透视、产品高光重建、复杂生成式 AI 贴图、AI 质检或自动重试。
- 未实现多 SKU 自动批量生成、Logo 修改后批量联动重生成，均留到 Step 6。
- 未接入企业微信、ERP、CRM、供应商或其他外部系统。
