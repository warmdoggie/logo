# 下一阶段：透明母版与生产 Logo 衔接

本次沿用 Node.js + SQLite、现有页面与工艺规则；所有验证使用隔离测试数据库。

## 已完成

- 原始 Logo → 透明母版的持久化接口及自动生成页入口。
- 保留已有透明通道；白、黑、彩色近纯底色的边缘连通分离；保留内部颜色。
- READY、REVIEW_REQUIRED、DESIGNER_REQUIRED 三种状态。简单去底需要设计师复核；复杂背景和全透明空图转人工。
- 母版记录来源、算法版本、文件哈希、处理详情、复核人及依据。同源重复处理复用，原文件不覆盖。
- READY 母版生成 ORIGINAL 生产 Logo，新建历史版本，保留来源关联。无当前生产 Logo 且无需复核时，页面可自动建立版本；有当前版本时必须显式选择使用，避免覆盖用户选择。
- 设计师/管理员复核权限；过期提交冲突保护；生产版本及原图重启恢复。
- 接入管理员任务删除预览及文件清理，继续保护共享文件。
- 延续自动生成结果文件哈希校验，缺失/损坏时重新生成新版本。

## 数据库新增

TransparentMaster：来源、版本、哈希、处理状态、文件引用、复核记录。
TransparentMasterProduction：透明母版与 ProductionLogo 的来源关系。
不改写旧母版、旧 Logo、任务绑定或效果图。

## 使用路径

任务详情 → 按方案自动生成 → 客户 Logo 自动背景处理。
选择原始 Logo 版本，点击“自动处理 Logo”。需要复核时，设计师在规则中心登录后返回，检查原图与结果并填写复核依据。
复核通过后，点击“使用此母版建立当前生产 Logo”。随后继续使用现有自动方案生成。
背景复核不代表工艺通过；颜色、渐变等未知信息仍可能触发补资料，硬禁止不能绕过。

## 安装边界

这是完整开发源码包，包含 seed 测试素材，不含 data、用户素材、密钥、密码、node_modules、测试临时数据。
请先复制原“最新开发副本”到独立测试目录，再用此包更新该副本的代码，保留 data；不要覆盖正式项目或把开发数据库覆盖正式数据库。
现有打包 Node 运行时可继续使用；普通 Node 首次运行需 npm install。
测试副本请设置 PORT=3211、APP_DATA_DIR 指向该副本 data 的绝对路径、APP_NO_SEED=1，然后 node server.mjs。原双击启动仍指向3210，不应用来和正式服务同时启动测试副本。
