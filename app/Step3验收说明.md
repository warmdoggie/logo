# Step 3 Logo 预处理与生产版本交付说明

当前本机工具已加入 Logo 预处理与 Production Logo 版本功能。继续使用 SQLite，原有产品、任务、母版版本和原始文件保留。地址仍为 http://127.0.0.1:3210/ ，双击启动入口不变。

## 1 已完成功能

- 任务详情增加 Logo 预处理入口，显示原始 Logo 最新版本、Production Logo 状态及当前版本。
- 现有每个任务的原始 Logo 作为 Original V1 保留。重新上传创建 V2、V3，不覆盖旧文件。
- 原图显示文件名、格式、尺寸、版本、时间、上传人标记和最新状态，并支持下载原始字节文件。
- 支持 PNG、JPEG、WebP 和独立静态 SVG；SVG 原文件保留，另生成 PNG 副本供预览和像素处理。
- 提供完整 Logo 选择、多个矩形元素框选、命名、六种元素类型、勾选组合和删除。
- 元素坐标使用 0–1 标准化坐标；组合采用联合外接矩形，保持相对位置与比例，选区外像素设为透明，不自动重排文字或图形。
- 保留原有透明通道，提供容差 0–120 的简单白底去除。
- 提供主色估算、复杂度提示、半透明检测、疑似渐变提示及人工确认标记。
- 支持保留原色、单色、双色；主次色可自定义 HEX，双色可交换颜色；提供黑、白、金、银快捷色和 Pantone 文字备注。
- 实时显示所选原色组合与 Production Logo，支持深浅棋盘查看白色 Logo。
- 创建生产版本并下载 PNG，保留历史只读内容，可将任一历史版本设为任务当前版本。
- Production Logo 由任务所有 SKU 共用，预留效果图关联数量及切换提示，不生成效果图。

## 2 SQLite 结构

为了避免破坏 Step 1 中 LogoAsset.taskId 的唯一约束，本次保留旧 LogoAsset 表，新增兼容版本表。业务能力与需求文档中的版本化 LogoAsset 等价。

| 表或字段 | 用途 |
| --- | --- |
| OriginalLogoVersion | id、taskId、version、legacyLogoAssetId、原始 filePath、previewPath、fileName、mimeType、width、height、createdBy、createdAt；taskId 与 version 联合唯一 |
| LogoElement | 所属 OriginalLogoVersion、名称、类型、标准化坐标、isFull、isArchived、createdAt |
| ProductionLogo | 所属任务、来源原图、版本、颜色模式、估算主色及输出色数、颜色值、备注、分析字段、背景处理参数、PNG 路径、尺寸、元素快照、创建者和时间 |
| ProductionLogoElement | 生产版本与原始元素的关联，防止元素来源丢失 |
| LogoUsageReference | 预留生产 Logo 与后续效果图的引用记录，用于计算关联数量；目前没有效果图生成模块写入它 |
| Task.activeProductionLogoId | 当前使用的生产版本引用；切换时只更新这个字段 |

旧产品库、多 SKU 关系、ProductTemplate、TemplateZone 和 TaskProductTemplate 均未重构。任务原有状态不改变，通过 activeProductionLogoId 在页面显示“Logo 已处理”。

## 4 操作路径

任务中心 → 查看任务 → Logo 预处理。

左栏为 Original Logo：查看历史或选择文件，再点“上传为 Original V2”。原有版本继续保留。上传新源文件不会自动切换已经确认的 Production Logo。

中栏为 Element：点击“使用完整 Logo”，或点击“新增元素”并在原图拖出矩形，填写名称和类型后“保存元素”。勾选本次需要的元素；完整 Logo 与局部元素互斥。多个选区可以重叠，重叠像素只保留原图，不进行重复叠加。

右栏为 Production Logo：选择背景模式和容差，选择保留原色、单色或双色，检查组合、透明预览及检测提示，再点击“创建 Production Logo V1”。以后每次保存产生新版本。历史下拉框打开只读版本，点击“设为当前版本”切换任务引用。

元素保存即持久化。颜色设置、尚未保存的框选及生产预览不是自动保存草稿；离开存在修改的页面时会提示。

## 5 颜色检测实现与限制

图片在本机用现有运行环境内的 Sharp 0.35.4 解码为 RGBA 像素。处理不使用生成式 AI，也不重建字体、字距或图形。

主色估算会对像素采样，将 RGB 按固定步长归组，优先使用相对稳定的内部像素，减少抗锯齿边缘被误算为额外主色。过滤小比例色组后合并近似色，返回 ONE、TWO、THREE、MORE_THAN_THREE 或 UNKNOWN。

该结果可能忽略面积很小的颜色，或将相近颜色合并；细线、小图、压缩噪声、浅色图形和大量半透明像素可能降低准确性。

半透明由被采样像素的 Alpha 判断，完全透明背景不算半透明效果。大量颜色过渡或较高半透明比例会标记“疑似渐变”；没有足够依据时使用未知值，不假装已排除渐变。

**阴影目前无法可靠区分，hasShadow 保存为未知并显示人工确认。** 所有分析都会明确要求人工核对，不代表工艺可制造结论。

去白底仅采用阈值：三个颜色通道都达到 255−容差的像素变透明，其余像素保留。它可能去掉 Logo 内的白色部分，也可能保留灰边或复杂背景。结果不合适时需要人工提供透明素材，不会启动 AI 抠图。

单色转换仅修改非透明像素的 RGB，保留 Alpha 与位置。双色使用确定性的二组颜色聚类，再映射主次色，同样保留像素位置及 Alpha。抗锯齿或压缩边缘可能被映射到另一组颜色；效果不合适时应回到单色或原色。单色来源未必会产生两个有效颜色，页面显示实际输出色数。

SVG 支持独立静态图形；拒绝外部资源、脚本、动画、foreignObject 等动态或引用内容。最多 12 MB、1600 万像素。复杂 SVG 可由用户导出为透明 PNG；原始 SVG 下载保持字节不变。

金色和银色只是视觉色。Pantone 备注仅作为文字记录，不自动换算为印刷色，也不判断烫金、烫银或丝印能力。

## 6 生产版本管理

版本号在每个任务内递增。保存过程重新在服务端计算输出，不信任浏览器预览文件；随后在事务中保存版本、元素关联和当前版本引用。保存失败会回滚记录并清理本次输出文件。

每版记录来源 Original 版本、所选元素完整快照、颜色模式与颜色值、背景处理方式和容差、分析结果、文件路径、创建时间及本机用户标记。重复页面使用过时版本保存会被拒绝，避免覆盖新版本。

删除元素采用归档方式：从制作列表隐藏，历史生产版本仍能读取原名称、类型、坐标和选区快照。没有更新历史生产文件或修改历史版本内容的接口。

当前版本只能指向当前任务自己的生产版本。切换旧版本不改变其他版本，也不触发效果图生成。

## 7 回归与验收

A：透明黑色 Logo 检测为 1 色；单色黑色输出与输入 RGBA 一致，包括半透明边缘。

B：包含图形、品牌、口号和装饰的测试图只选图形与品牌；输出保留原相对位置，未选择的内部装饰和外部口号被排除。

C：五色测试素材提示建议适配；转换白色后，所有可见像素为白色，逐像素 Alpha 与原图一致。

D：双色输出仅含指定主次 RGB，尺寸和 Alpha 与来源一致。

E：连续保存生产版本、归档历史选用元素、切换当前版本后，原始来源与旧 PNG 保留不变；拒绝空选择、越界、已删除或不属于来源的元素、过时版本及完全透明输出。

F：重启本地服务后，Original、Element、Production 版本和当前引用全部恢复。SVG 原始文件字节核验通过。

浏览器测试通过任务入口、原图上传、元素拖选、颜色与背景实时预览、生产 V1/V2、当前版本切换、历史只读及窄屏检查。Step 1 与 Step 2 接口回归通过；L0048 母版编辑浏览器回归也通过。

正式数据库升级后核对：原有 5 个产品、3 个任务、3 个母版版本、9 个母版区域，以及全部原有关系记录的原字段未改变；原始上传文件 SHA-256 校验完全一致。为现有 3 个任务各建立 Original V1 兼容记录和一个“完整 Logo”元素。正式任务未自动创建 Production Logo。

## 8 Mock 和未实现能力

没有用 Mock 数据替代原始版本、元素、像素转换或生产版本保存。多色、组合图等验收使用明确的程序测试素材，未导入用户任务。

当前不含 AI 自动识别元素、复杂背景抠图、矢量重建、字体识别、可靠阴影判断或实际员工身份认证；上传人显示本机用户标记，不是已认证员工姓名。

效果图关联统计接口已预留，但本阶段没有真实效果图模块，因此正式数据关联数量为 0。没有实现工艺规则、效果图贴图、批量重新生成及外部系统对接。

启动入口仍为“双击启动AI效果图智能助理.cmd”或 start.cmd。图像处理复用当前电脑运行环境的 Sharp；若将项目迁移到其他电脑，需要提供兼容 Node.js 与 Sharp 运行环境。

开发者可运行 `node --test test.mjs test-step2.mjs test-step3.mjs` 复核接口与像素级验收。测试使用隔离数据目录，不修改正式任务。
